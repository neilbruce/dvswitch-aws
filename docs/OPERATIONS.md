# DVSwitch AWS NCS Operations Guide

## Architecture Diagram

```text
Browser (React NOC UI)
        |
        v
Apache reverse proxy (TLS, security headers)
        |
        v
Gunicorn + Flask API
        |------------------ SQLite now / PostgreSQL later via DATABASE_URL
        |------------------ SQLAlchemy models + Alembic baseline
        |------------------ APScheduler jobs (Asia/Kolkata)
        |
        +--> DVSwitch tune script (no shell=True)
        +--> systemctl allow-list for Apache/Gunicorn/DVSwitch/Analog_Bridge/MMDVM_Bridge
        +--> MMDVM / DVSwitch / Analog_Bridge log cursors
        +--> RadioID HTTPS cache
        +--> BrandMeister HTTPS sync/status APIs
        +--> APRS-IS TCP receive connection
        +--> ADIF/CSV exports and backup archives
```

## Deployment Guide

1. Configure required environment variables before install:
   - `STATION_CALLSIGN`
   - `STATION_DMR_ID`
   - `SECRET_KEY` (optional; generated by installer when omitted)
   - `INITIAL_ADMIN_USERNAME` (optional, default `admin`)
   - `INITIAL_ADMIN_PASSWORD` (optional; generated by installer when omitted)
   - APRS variables when using a production APRS-IS passcode.
2. Run the installer from the repository root or pipe it through root shell after publishing it:
   ```bash
   sudo STATION_CALLSIGN=YOURCALL STATION_DMR_ID=1234567 ./deploy/install.sh
   ```
3. The installer creates `/etc/dmr-ncs.env`, initializes SQLite, stamps the Alembic baseline, configures Apache/systemd, and starts `dmr-ncs.service`.
4. Load BrandMeister talkgroups from the UI Sync button or `POST /api/talkgroups/sync` as an authenticated Admin/Operator.

## Upgrade Guide

1. Back up first: `sudo /opt/dmr_ncs_system/backup.sh`.
2. Copy the new repository contents into `/opt/dmr_ncs_system`.
3. Activate the virtualenv and install updated requirements:
   ```bash
   cd /opt/dmr_ncs_system
   . venv/bin/activate
   pip install -r requirements.txt
   alembic -c alembic.ini upgrade head
   ```
4. Restart services:
   ```bash
   sudo systemctl restart dmr-ncs.service apache2
   ```

## Rollback Guide

1. Stop the application: `sudo systemctl stop dmr-ncs.service`.
2. Restore the latest known-good backup with `sudo /opt/dmr_ncs_system/restore.sh /opt/dmr_ncs_system/backups/<archive>.tar.gz`.
3. Verify `/etc/dmr-ncs.env` still contains station identity and secrets.
4. Restart Apache and the app service.

## Security Review

- Secrets are loaded from `/etc/dmr-ncs.env`; source-controlled service files no longer contain secrets.
- Flask refuses startup when required secrets or station identity are missing.
- Passwords use Werkzeug `scrypt` hashes.
- Login failures lock accounts for 15 minutes after five failures.
- Session cookies are HTTP-only, SameSite, and secure by default.
- Service control uses `subprocess.run([...])` with explicit argument arrays and an allow-list.
- Debug mode is disabled.
- ADIF exports validate callsign, DMR ID, and timestamp fields before generation.

## Future Architecture Reservation

Future browser TX/RX, WebRTC audio, SIP bridge, and multiple-hotspot support should be added as separate bounded services:

- `audio_gateway`: isolated WebRTC/SIP media service, no direct Flask media handling.
- `hotspot_registry`: database table for multiple DVSwitch/MMDVM endpoint profiles.
- `ptt_policy`: RBAC and station-identity authorization for browser TX.
- `media_audit`: immutable transmit/receive event log.

No transmit audio functionality is enabled in this change set.
